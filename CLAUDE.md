## Project Overview

Z_COM is a PySide6 serial communication debugging tool supporting three transport modes: Serial (pyserial), J-Link RTT (pylink-square), and TCP/UDP Socket. Python 3.13+, Windows primary, cross-platform design.

## Commands

```bash
# Run the app
python run.py

# Run all tests
pytest

# Run a single test file
pytest tests/test_logger.py

# Run a single test
pytest tests/test_logger.py::test_log_creates_file

# Compile UI (after editing .ui files)
pyside6-uic ui/main_window.ui -o ui/Ui_main_window.py
pyside6-uic ui/serial_settings_dialog.ui -o ui/Ui_serial_settings_dialog.py
pyside6-uic ui/extended_send_widget.ui -o ui/Ui_extended_send_widget.py
pyside6-uic ui/extended_send_editor_dialog.ui -o ui/Ui_extended_send_editor_dialog.py

# Package
python pack.py            # PyInstaller -> dist/
python pack_nuitka.py     # Nuitka -> dist_nuitka/
```

No CI, lint, format, or typecheck configuration exists.

## Architecture

```
src/
  main.py                 -- Entry point, multi-instance detection via file locks
  version.py              -- VERSION, APP_NAME, ICON_PATH
  build_info.py           -- BUILD_TIME (auto-generated by pack scripts, do not edit)
  core/                   -- Business logic
    config_manager.py     -- JSON config load/save with debounce
    data_handler.py       -- bytes <-> HEX/ASCII, control char display (U+2400~U+2421)
    logger.py             -- Thread-safe buffered daily log writer
    ansi_parser.py        -- ANSI CSI SGR -> HTML <span>
    extended_send_manager.py -- Multi-item send orchestration (single/multi/loop)
  io/                     -- Transport layer
    io_transport.py       -- Abstract base: IOTransport(QObject) with shared signals
    serial_manager.py / serial_reader.py   -- pyserial, 50ms frame-batching QThread
    rtt_manager.py / rtt_reader.py         -- pylink-square QThread
    socket_manager.py / socket_reader.py   -- TCP/UDP, select()-based QThread
  windows/                -- UI classes (import generated Ui_*.py, add logic only)
    main_window.py        -- MainWindow, ~910 lines, data flow hub
    serial_settings_dialog.py
    extended_send_widget.py
    extended_send_editor_dialog.py
ui/                       -- .ui source files + generated Ui_*.py (never hand-edit)
config/                   -- Runtime JSON config (settings, extended_send, presets, dap_devices)
tests/                    -- pytest suite with qapp fixture for Qt tests
```

**Data flow**: Reader QThread emits `data_received(bytes)` -> `MainWindow._on_data_received()` -> batched in `_pending_receive_data` with flush timer -> `_append_data_lines()` -> display + log.

**IO switching**: `MainWindow._io` property returns the active manager based on `self.io_mode` (`'serial'|'rtt'|'socket'`). All three managers share the same `IOTransport` signal interface.

## Key Conventions

- **Entry point is `run.py`**, not `src/main.py`. `run.py` adds project root to `sys.path`.
- **sys.path manipulation**: `main_window.py`, `extended_send_widget.py`, `serial_settings_dialog.py`, `extended_send_editor_dialog.py` manually insert project root into `sys.path` to resolve `ui/` imports. This is required for both dev and packaged modes.
- **UI workflow**: `.ui` files are the single source of truth for layout. Never hand-edit `Ui_*.py`. Signal connections and business logic go in `src/windows/` runtime classes only.
- **Multi-instance**: File-lock based (`msvcrt.locking` on Windows, `fcntl.flock` on Linux). Instance 1 uses `config/` and `logs/`; instance N>1 uses `instance_N/config/` and `instance_N/logs/`.
- **Frame timeout**: `SerialReaderThread` batches incoming bytes with a 50ms timeout, configurable in settings.
- **Config debounce**: `ConfigManager` saves with 500ms debounce for frequent changes, immediately for infrequent ones.
- **Display pruning**: `MainWindow` limits display to 5000 lines, checks every 50 appends. 10-second timer flushes logs, extended send config, and calls `gc.collect()`.
- **Cross-platform**: Do not use Windows-only APIs. Prefer Python stdlib or cross-platform libraries.
- **Socket mode**: 4 fixed entries (TCP/UDP x Server/Client). TCP Server sends only to the latest connected client.
- **Extended send**: `sort_order=0` means excluded from sending. Duplicate order values trigger a warning.
