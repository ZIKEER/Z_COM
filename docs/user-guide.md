# 使用与功能说明

## 通信后端

### 串口

- 支持任意正整数波特率、5–8 数据位、1/2 停止位、无/奇/偶校验、无/XON-XOFF/RTS-CTS 流控和帧超时。
- 波特率可从常用值中选择或手动输入 `1..10000000`，程序保存最近 12 个使用值。
- 连接期间可直接修改全部串口参数。驱动拒绝修改时恢复原参数，并在报文区和日志中记录原因。
- 参数组合最终是否可用取决于操作系统、串口设备和驱动能力。

### Socket

- 支持 TCP Client、TCP Server、UDP Client 和 UDP Server。
- Server 自动枚举本机 IPv4 地址，并提供 `0.0.0.0`、`127.0.0.1`；地址也可手动输入。
- TCP Server 只保留最新客户端。新连接会顶替旧连接，并记录新旧客户端地址；两条连接的残留数据不会混为一帧。

### 调试探针 RTT

- J-Link 动态加载 SEGGER 官方 SDK；CMSIS-DAP、ST-Link 和通用调试适配器使用 probe-rs。
- 两种后端均使用 RTT 上行/下行通道 0，按指定 MCU 连接，不进行大范围内存扫描。
- 默认隐藏通用 FTDI/JTAG 适配器，可在“更多设置”中开启。
- J-Link RTT 暂时失效时自动恢复，连续失败后重新打开会话。
- 串口、探针、网卡和自定义目标枚举均在后台执行，不阻塞界面。

J-Link SDK 查找顺序：

1. “更多设置”中保存的动态库或安装目录。
2. 程序同级目录。
3. `JLINK_PATH` 环境变量。
4. 系统常见安装目录。

未安装 J-Link SDK 只会禁用 J-Link，不影响串口、Socket 和其他 probe-rs 探针。更多差异见 [双 RTT 后端说明](rtt-backends.md)。

## 报文显示

- 提供 HEX、ASCII 和 HEX+ASCII 三种模式。
- 接收使用 `←`，发送使用 `→`；时间、方向、格式标签和通信数据分别着色。
- 控制字符显示为 Unicode 控制图符，非 ASCII 字节显示为 `\xNN`。
- ASCII 和 HEX+ASCII 模式支持 ANSI SGR 粗体、下划线、16 色、256 色和 RGB 真彩色；畸形或不完整序列不会中断接收。
- 支持自动滚动、5000 行裁剪、复制、全选、清空和 ANSI 显示开关。
- 清空报文区会同时将收发字节计数归零，不删除已经写入的日志。
- 连接、断开、错误、警告、客户端变化和 RTT 恢复等事件也写入报文区和日志。
- 接收/发送区域、接收/扩展发送区域均可拖动，比例自动保存。

## 发送

- 普通发送支持 ASCII、HEX 和追加 CRLF。
- 自动发送支持自定义发送间隔。
- 扩展发送支持单条、按序号、多条和循环发送，以及延时、排序、删除、移动、JSON 导入导出和自动保存。
- 扩展发送 ASCII 支持 `\r`、`\n`、`\t`、`\0`、`\\`、`\xNN` 转义。
- 所有入口都会拒绝空数据、奇数半字节 HEX、非法 HEX 字符及未知或不完整转义。
- 发送成功后，报文区立即显示发送内容并更新计数。

## 配置、日志与多实例

Z_COM 以单个可执行文件发布，不要求许可证或资源文件伴随运行。首次启动后，运行数据
位于主程序同级目录，不使用系统用户配置目录：

```text
主程序所在目录/
├── Z_COM.exe                  Windows；Linux 为 Z_COM
├── config/
│   ├── settings.json
│   ├── extended_send.json
│   └── probe_rs_targets/
├── logs/
├── locks/
└── instance_N/               第 2 个及之后的实例
```

- `settings.json` 保存通信参数、显示偏好、分隔区域比例和 J-Link SDK 路径。
- `extended_send.json` 保存扩展发送条目。
- `probe_rs_targets/` 保存自定义 probe-rs MCU YAML。
- `logs/log_YYYY-MM-DD.txt` 按本机日期每天一个文件，跨午夜自动切换。
- 日志包含毫秒级时间、收发方向、HEX、ASCII 和后端事件。
- 程序不提供手动保存日志，现场数据始终自动记录。
- 多实例通过文件锁分配编号；实例 2+ 使用独立的 `instance_N/config` 和 `instance_N/logs`。
- 实例编号显示在状态栏、About 和非首实例窗口标题中。
- Windows 可执行文件包含精简的项目文件图标；窗口或任务管理器最终显示效果由
  Windows/WebView 处理，不在运行时加载额外图标资源。

## About

About 页面显示软件版本、构建时间、通信后端、实例编号和数据目录，并提供 GitHub、
Gitee 代码仓库超链接。

“开源许可”可在完全离线的情况下查看内嵌的 Apache-2.0 `LICENSE`、项目 `NOTICE`
和 `THIRD_PARTY_NOTICES`。这些内容属于可执行文件的一部分，不需要在 EXE 同级目录
放置文本文件。

### 软件更新

1. 点击“检查更新”，程序同时查询硬编码的 GitHub 与 Gitee Release。
2. 分别查看 GitHub、Gitee 获取到的版本，以及高于、等于或低于当前版本；检测失败时查看对应来源的错误。
3. 发现新版本后查看版本说明、下载来源、文件大小和镜像状态。
4. 点击“下载更新”，程序把当前平台执行文件写入主程序同级 `.update/`。
5. 下载过程显示进度，完成后校验 `release-manifest.json` 声明的文件大小与 SHA-256。
6. 点击“安装并重启”并确认，程序断开通信、刷新日志、启动临时更新进程并退出。
7. 更新进程备份旧程序、替换为新程序并重启；替换或启动失败时恢复 `.bak`。

更新不会静默下载或安装。安装前必须关闭其他 Z_COM 实例，并由实例 1 执行。GitHub 与 Gitee 同版本文件校验信息不一致时，程序拒绝更新；只有版本、文件名、大小和 SHA-256 一致的来源才能作为备用镜像。

网络检查失败不影响串口、Socket 和 RTT。单个来源失败时不会再根据另一个旧版本来源误报“当前已是最新版本”，检测结果和错误会显示在 About 页面并写入当日日志。更新进程失败时原因写入 `.update/update-error.log`，下次启动会显示错误并继续使用原版本。
